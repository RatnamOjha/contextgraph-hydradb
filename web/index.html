OVERVIEW

Context for agents, selected by relationships

ContextGraph reads task-to-skill, skill-to-tool, and tool-to-prerequisite relationships from HydraDB. It exposes the relevant tool definitions to a deterministic runner or a real Groq agent. Read tools query the historical Olist subset in SQLite; returned facts are checked independently against task objectives.

ARCHITECTURE

Two stores, separate jobs

Task→FastAPI router→HydraDB relationships→Olist tool runner→Objective verifier

HydraDB stores catalog relationships and anonymized entity links. SQLite stores historical Olist business records. The verifier checks objective-level answers against tool output evidence.

PLAYGROUND

Run an order task

  1. Select a historical Olist order.
  2. Choose a task example or ask a focused question.
  3. Choose deterministic execution for repeatable runs or Real Groq for model-selected calls.
  4. Inspect retrieved tools, actual calls, answer objectives, and evidence.

Groq mode requires a server-side key and does not fall back to fixture execution if the provider fails.

RETRIEVAL

Directional prerequisites

A dependency edge order.items → order.details means selecting order.items expands retrieval to include order.details. A status-only task rooted at order.details should not pull in order.items.

VERIFICATION

Tool calls are not task completion

Outcome labels reflect requested objectives and source evidence. A completed tool call can still leave an objective UNVERIFIED when the answer is absent, incomplete, or unsupported.

LEARNING LAB

Retrieval filter versus persisted mutation

The hosted Learning Lab excludes an existing edge from retrieval for one run and later verifies the persisted relationship remained unchanged. The local isolated script writes and reads back a graph edge, runs held-out tests, then deletes it and verifies exact rollback. Those are distinct experiments.

LIMITATIONS

Read the evidence in scope

  • The Olist dataset is a historical demo sample, not a live commerce system.
  • The graph-learning benchmark has three held-out orders and deterministic execution.
  • Context tokens are estimates from serialized tool definitions.
  • Learning validation uses declared prerequisite metadata; it does not demonstrate autonomous discovery.
  • The optional MCP adapter is a thin client to the FastAPI APIs; it does not add tool execution.
